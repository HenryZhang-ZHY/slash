Slash 是一个 GitHub App：在拉取请求上评论 `/deploy staging`，Slash 就会在你
自己的 GitHub Actions 上触发 `workflow_dispatch`，并把它的状态以 check run 的
形式同步回 PR。

## 1. 创建账户

Slash 以托管服务的形式运行 —— 在 Slash 控制台登录（或注册新账户），按 onboarding
创建你的第一个团队。登录和 onboarding 流程见
[Web 控制台](/zh-hans/web-console/)。如果你想在自己的基础设施上运行 Slash，参见
[自托管](/zh-hans/self-host/)。

## 2. 创建 GitHub App

在 GitHub 上创建一个 GitHub App（个人账户或组织均可），并配置：

- **Webhook URL**：你的 Slash 部署提供的 webhook 端点（云服务或自托管）
- **Webhook secret**：一个随机值
- **权限**：`checks: write`、`actions: write`、`contents: read`、
  `pull_requests: write`、`issues: write`、`metadata: read`（参见
  [权限](/zh-hans/permissions/) 了解每个权限的用途 —— 尤其是
  `issues: write` 很容易被低估，缺了它整个产品都无法工作）
- **订阅事件**：`issue_comment`、`workflow_run`、`check_run`、
  `pull_request`

为 App 生成私钥。在你希望运行命令的仓库（或仓库们）上安装这个 App，然后在 Slash
控制台里连接它，让 Slash 能收到它的 webhook。

## 3. 配置一条命令

在仓库的**默认分支**上添加 `.slash/echo.yml`：

```yaml
command: echo
permission: write
workflow: echo.yml
args:
  - name: message
    free_text: true
```

完整的 schema 参见 [`.slash/` 参考](/zh-hans/slash-config-reference/)；你也可以在
自己的 CI 里运行 `slash validate .slash/`，在合并到默认分支之前发现错误（参见
[已知限制](/zh-hans/limitations/) —— Slash 目前不会在 push 时自行校验 `.slash/`）。

## 4. 添加 workflow

同样在默认分支上添加 `.github/workflows/echo.yml`（GitHub 只从默认分支注册
`workflow_dispatch` 目标 —— 参见
[workflow 要求](/zh-hans/workflow-requirements/)）：

```yaml
name: echo
on:
  workflow_dispatch:
    inputs:
      message: { required: false }
      slash_actor: { required: false }
jobs:
  echo:
    runs-on: ubuntu-latest
    steps:
      - name: Echo
        env:
          MESSAGE: ${{ inputs.message }}
          ACTOR: ${{ inputs.slash_actor }}
        run: echo "$ACTOR says: $MESSAGE"
```

两个文件的完整可复制版本在仓库的
[`examples/` 目录](https://github.com/HenryZhang-ZHY/slash/tree/main/examples) 里。

## 5. 试试看

打开一个拉取请求并评论：

```text
/echo hello world
```

几秒内你应该会在评论上看到 🚀 反应，PR 上出现 `slash/echo` check run，并在
workflow run 结束后达到终态，附上该 run 的链接。
