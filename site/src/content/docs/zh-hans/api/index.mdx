Slash 从同一来源提供 HTTP API 和 Web 控制台。把示例里的 `https://slash.example.com`
替换为你 Slash 部署的 origin。控制台（见[账户与工作区](/zh-hans/account/)）是这些
端点的薄客户端。

所有请求体共享一个 **5 MiB 限制**。UUID 路径参数使用标准连字符 UUID 表示。
JSON 响应里的时间戳是 RFC 3339 字符串。

## 选择 API

- 使用[认证与团队](/zh-hans/api/authentication/)处理 session、外部身份、当前用户和
  团队创建。
- 使用[个人 Access Token](/zh-hans/api/access-tokens/)为 Agent 和其他 REST 客户端
  签发凭据。
- 使用[Test Engine 管理](/zh-hans/api/test-engine/)操作 suites、tests、execution
  历史、状态和 collection tokens。
- 从 CI 使用[测试结果 Ingestion](/zh-hans/api/ingestion/)上传结果或查询隔离状态。
- 配置或监控服务器边界时，使用[Webhook 与运维](/zh-hans/api/platform/)。

## 认证方式

| 表面 | 认证 |
| --- | --- |
| 账户、团队和 Test Engine 管理 | `slash_session` cookie 或个人 Bearer token |
| 个人 Access Token 管理 | 仅 `slash_session` cookie |
| 测试结果 ingestion 与隔离查询 | `Authorization: Bearer <collection-token>` |
| 实例管理 | 由 `SLASH_ADMIN_SECRET_PATH` 开启的独立 admin session |
| GitHub webhook | `X-Hub-Signature-256` HMAC 签名 |
| 健康与指标 | 无 |

## 端点清单

下面这些表列出 `slash-server` 注册的每条路由。

### [认证与团队](/zh-hans/api/authentication/)

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/auth/register` | 创建账户和会话 |
| `POST` | `/api/auth/login` | 创建会话 |
| `POST` | `/api/auth/logout` | 清除当前会话 |
| `GET` | `/api/auth/me` | 读取当前用户、团队和连接 |
| `GET` | `/api/auth/github/sign-in` | 开始 GitHub 登录 |
| `POST` | `/api/auth/github/connect` | 把 GitHub 连接到当前用户 |
| `GET` | `/api/auth/github/callback` | 完成 GitHub 认证 |
| `POST` | `/api/teams` | 创建团队 |

### [个人 Access Token](/zh-hans/api/access-tokens/)

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/access-tokens` | 列出当前用户的 token |
| `POST` | `/api/access-tokens` | 创建并一次性显示 token |
| `DELETE` | `/api/access-tokens/{id}` | 撤销 token |

### [Test Engine 管理](/zh-hans/api/test-engine/)

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/test-engine/suites` | 列出拥有的套件 |
| `POST` | `/api/test-engine/suites` | 创建或复用套件 |
| `GET` | `/api/test-engine/suites/{id}/tests` | 列出套件里的测试 |
| `GET` | `/api/test-engine/tests/{id}/executions` | 列出执行历史 |
| `PATCH` | `/api/test-engine/tests/{id}/state` | 改变测试的处置状态 |
| `GET` | `/api/test-engine/suites/{id}/tokens` | 读取最新有效 token |
| `POST` | `/api/test-engine/suites/{id}/tokens` | 签发 collection token |
| `POST` | `/api/test-engine/suites/{id}/tokens/revoke` | 吊销 collection token |

### [测试结果 ingestion](/zh-hans/api/ingestion/)

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/v1/test-engine/upload` | 上传归一化 JSON 或 JUnit XML |
| `POST` | `/v1/test-engine/upload/cargo` | 上传 Cargo libtest JSON 事件 |
| `POST` | `/v1/test-engine/upload/vitest` | 上传 Vitest 结果 |
| `GET` | `/v1/test-engine/quarantined` | 列出 muted 或 skipped 的测试名 |

### [实例管理](/zh-hans/self-host/operations/#实例管理后台)

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/admin/auth/login` | 创建 admin session |
| `POST` | `/api/admin/auth/logout` | 清除 admin session |
| `GET` | `/api/admin/auth/session` | 读取 admin session 状态 |
| `GET` | `/api/admin/overview` | 读取实例队列和 installation 汇总 |
| `GET` | `/api/admin/installations` | 列出已知 App installations |
| `POST` | `/api/admin/installations/refresh` | 从 GitHub reconcile installations |

## 错误约定

账户和团队端点返回这种形状的 JSON 错误：

```json
{
  "error": "invalid email"
}
```

创建套件端点用 `{ "message": "..." }` 表示校验和所有权冲突。其他 Test Engine 管理和
ingestion 失败可能返回空 body，带文档里描述的 HTTP 状态码。

未知的 `/api/*` 路由返回 `404` 与 `{ "error": "not found" }`。
