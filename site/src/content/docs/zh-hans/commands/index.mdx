Slash 命令把拉取请求评论转换成一次 GitHub Actions workflow run。Slash 负责控制面：
解析评论、检查调用者当前的仓库权限、创建 check run、dispatch workflow，并同步最终
结果；真正执行 workflow 的仍是你的 GitHub Actions runner。

## 一条命令如何运行

1. 贡献者在拉取请求评论的第一行输入 `/command arguments`。
2. Slash 从仓库默认分支读取全部 `.slash/*.yml` 文件，组成一个原子命令目录。
3. Slash 校验调用者当前的 GitHub 仓库角色；无法确认授权时拒绝命令。
4. Slash 创建 `slash/<command>` check run，并针对拉取请求的 head 分支 dispatch
   配置的 `workflow_dispatch` workflow。
5. Slash 跟踪 workflow run，并把终态同步到最初的 check run。

目前只支持 head 分支属于同一仓库的拉取请求。配置与授权策略始终来自默认分支，
因此拉取请求中的代码无法放宽自己的权限门槛。

## 查看可用命令

在拉取请求评论的第一行输入：

```text
/slash help
```

Slash 会回复仓库默认分支上通过校验的命令。每条内容包含用法、所需 GitHub 角色、
参数详情和可复制修改的示例。Help 不会启动 workflow，也不会创建 check run。如果
命令目录缺失、无效或暂时不可用，Slash 会报告对应状态，不会展示不完整的 help。
