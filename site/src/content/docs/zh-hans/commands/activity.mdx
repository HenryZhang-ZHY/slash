Slash 的认证控制台会按仓库展示已接受斜杠命令的历史。点击导航中的**命令活动**，或直接
打开部署上的 `/activity`。

## 授权仓库访问

打开活动前，请先从账户菜单的**账户设置**连接 GitHub 身份。Slash 使用该身份发现你可以访问的
GitHub App 安装实例和仓库。短期发现授权到期后，页面会要求再次授权 GitHub。

仓库发现本身不会授予历史读取权限。每次返回历史前，Slash 都会向 GitHub 确认已连接
身份对所选仓库仍至少拥有读取权限；公开仓库也执行同一检查。Slash 不会透露你当前
无法读取的仓库。

## 选择并筛选活动

先选择 GitHub App 安装实例，再选择仓库。仓库选择会写入 URL，因此可以加入书签。
你可以按精确生命周期状态或命令名筛选，通过**加载更多**读取更早页面，并用**刷新**
查看较新的状态变化。页面不会在后台轮询。

每行显示触发时间、命令、拉取请求、触发者、当前结果、耗时，以及最相关 GitHub
check、workflow run 或评论的链接。Slash 不展示原始命令参数和内部失败诊断，因为
这些字段可能包含敏感输入或上游细节。

## 理解缺失记录

只有 Slash 接受并认领 invocation 后，活动才开始记录。运行中、已完成、已中止、已
取代以及在分发或关联阶段失败的命令都会出现。格式错误的评论、未知命令、`/slash
help`、权限拒绝、无效配置和参数校验失败不会创建 invocation，因此不会显示。

如果仓库发现没有结果，请确认 Slash GitHub App 已安装到已连接身份可访问的账号。
如果所选仓库提示访问权限已失效，请选择其他仓库或向仓库所有者申请读取权限。GitHub
或 Slash 暂时出错时，页面会保留选择，便于安全重试。
