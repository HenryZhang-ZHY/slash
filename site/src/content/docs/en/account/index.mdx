The Slash console serves account, workspace, settings, and Test Engine screens
from the same origin as the REST API. Each screen reads and updates server-side
state through the documented API.

## Sign in or register

Open the deployment's console root. An unauthenticated visit redirects to
`/login`, where you can:

- create an account with an email and a password of at least eight Unicode
  characters;
- sign in to an existing password account; or
- sign in with a stable GitHub identity.

Authentication creates an `HttpOnly` session cookie. Slash does not use a
GitHub email address as an identity key and does not merge accounts by matching
email. If you already have a password account, sign in to that account before
connecting GitHub from Settings.

## Create your first team

A user without a team is sent to `/onboarding`. Enter a team name and a slug
containing lowercase letters, numbers, and hyphens, up to 63 characters.
Creating the first team also creates a home organization when needed and makes
you the team's maintainer.

Teams organize Slash-native resources such as Test Engine suites. GitHub
repository access independently controls who may invoke slash commands.

## Manage team members

Choose a Team under **Teams** in the console navigation, or select it from the
team list on the overview. The same Team links are available in the mobile
navigation. Members can read its roster.
Maintainers can invite an email as a member or maintainer, resend or revoke a
pending invitation, change roles, and remove members. Slash always preserves
at least one maintainer.

The email link works whether the recipient already has a Slash account or
needs to register. After sign-in, the browser returns to the invitation and
asks the recipient to accept it. Invitations expire after seven days and can
be used once.

## Use the console

The overview separates the two product areas: **Command automation** for
repository activity and **Test Engine** for test intelligence. It also shows
test totals and direct links to the teams you manage. Use the
[Test Engine console](/en/test-engine/console/) to create suites and inspect
results.

Use **Command activity** at `/activity` to inspect accepted slash commands for
repositories your connected GitHub identity can currently read. See
[Review command activity](/en/commands/activity/) for authorization, filters,
and troubleshooting.

## Connect GitHub

Open the account menu and choose **Account settings**, or go to `/settings`, to
view the GitHub identity linked to the account. If none is
linked, start the connection flow from that page. Slash resolves the connection
from the authenticated provider callback rather than trusting browser URL
parameters.

## Manage your password

Open **Account settings** to change an existing password or add password login to an
account that currently uses only GitHub or another external identity. Existing
password users must enter their current password. External-identity-only users
choose a unique login email and a password of at least eight characters.

Adding a password creates another sign-in method for the same account. Slash
does not merge it with an account that already uses the chosen email.

## Manage personal access tokens

**Account settings** also lets you create and revoke credentials for agents and REST API
clients. A token authenticates as its owning user and does not add permissions.
Its plaintext value is shown once; the token list later shows only its name,
creation time, last use, and expiry state.

See the [personal access token reference](/en/api/access-tokens/) for request
authentication, lifetime rules, and revocation behavior.

Language, appearance, release information, account settings, and sign-out are
grouped in the account menu. They are account-level controls rather than Team
or Test Engine suite settings.
