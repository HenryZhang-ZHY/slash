This tutorial starts with access to a running Slash console and ends with one
test execution visible in Test Engine.

## 1. Create a suite

Sign in to the Slash console, open `/tests`, and choose **Create suite**. Enter
the repository owner, repository name, and a stable suite key such as
`unit-tests`.

Slash creates the suite first. In its settings, choose **Create token**, give
the credential a name such as `GitHub Actions`, and keep the default **Never**
expiry or choose a finite date. Copy the token now; it is the bearer credential
your CI uses for this suite and is not recoverable later.

## 2. Store the collection token

Save the token as a secret in your CI system and expose it to the upload step as
`SLASH_COLLECTION_TOKEN`. Do not put it in repository configuration, command
arguments, logs, or test output.

## 3. Upload one execution

Replace the origin below with your Slash deployment and send a normalized
result:

```sh
curl -X POST \
  -H "Authorization: Bearer $SLASH_COLLECTION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"ci_provider":"github-actions","run_ref":"first-upload","executions":[{"name":"checkout::completes_order","status":"passed","duration_ms":87}]}' \
  https://slash.example.com/v1/test-engine/upload
```

A successful upload returns `200 OK` with an empty body. The collection token
selects the suite, so the request body does not contain a suite ID.

## Confirm the result

Return to `/tests`, select the suite, and find
`checkout::completes_order`. Its latest result should be `passed`, with one
recorded execution.

If the upload returns `401`, verify that the token is present, active, and not
expired. If it returns `400`, compare the payload with the
[ingestion schema](/en/api/ingestion/#normalized-json).
