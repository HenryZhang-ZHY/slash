Open `/tests` in the Slash console. The page is a user interface over the
documented Test Engine management API; state is stored on the server rather
than only in the browser.

## Manage suites

Use the suite selector to review all-time execution totals, pass rate, and
muted or skipped counts. Creating a suite requires an owner, repository, and
suite key. After Slash creates the suite, open **Collection setup** to create
its first collection token and review collector endpoints.

## Find and inspect tests

Filter tests by state, search by name, file, or label, and sort by recency,
name, duration, or failure count. Select a test to inspect its metadata,
aggregate history, and individual execution rows. Large filtered lists render
in bounded batches; use **Show more cases** to reveal the next batch.

The selected suite, view, test, or run is represented in the URL. Refreshing,
bookmarking, or sharing that URL restores the same inspection context. On a
small screen, selecting a test or run opens its detail view; use the explicit
back action to return to the list.

## Inspect runs

Switch to **Runs** to review each collected batch as a whole. The list shows
the provider and run reference, capture time, overall status, pass rate,
execution count, and total reported test duration. Select a run to inspect its
invocation metadata and every test execution captured in that run, including
source locations and failure output when reported.

Both run and execution history use bounded pages. Use **Load more** to retrieve
older runs or the remaining tests in a large run.

## Change test state

You can enable, mute, or skip a test. Muting keeps the test observable while
preventing its failure from blocking a pull request; skipping is a manual
decision that stops new execution evidence.

## Manage collection tokens

Create a named token for each CI collector or runner. The plaintext credential
is shown only when issued and should be moved directly into the CI system that
uploads results. Tokens do not expire by default; you can instead choose 30,
90, or 365 days, or a custom expiration date.

A suite may have multiple active tokens. **Rotate** creates a named replacement
without revoking the existing token, so you can switch CI safely and revoke the
old token when it no longer receives traffic. The console retains non-secret
creation, expiration, last-used, and revocation metadata for each token.

See [Tests and quarantine](/en/test-engine/concepts/) for state semantics and
the [management API](/en/api/test-engine/) for exact requests and errors.
