The grants management endpoints maintain the [grants](/en/grants/) that decide
who may invoke commands. All of them require a valid `slash_session` cookie and
an **org owner** role (`org_members.role = 'owner'`) — anyone else gets `403`,
fail-closed. A grant is immutable after creation: editing means delete and
re-create.

## GET `/api/grants`

Lists every grant in the caller's organization, with resolved subject and
granter names.

```sh
curl -b cookies.txt https://slash.example.com/api/grants
```

Success: `200 OK` with an array.

```json
[
  {
    "id": "3b6d4f12-9a41-4f88-a1c5-8a4d4b6e9f10",
    "subject_type": "team",
    "subject_id": "cb50f1d6-7a11-44d7-b45e-9c158b8e7774",
    "subject_name": "eng",
    "scope": "command",
    "repository": "acme/widgets",
    "command": "deploy",
    "permission": "write",
    "effect": "allow",
    "granted_by": "1165fc2c-64f4-49f6-b77c-15317cf59fb8",
    "granted_by_name": "Release Operator"
  }
]
```

| Status | Meaning |
| --- | --- |
| `200` | Grants listed |
| `401` | No valid session |
| `403` | The caller is not an org owner |
| `500` | Listing failed |

## POST `/api/grants`

Creates a grant. The request body uses camelCase:

```json
{
  "subjectType": "team",
  "subjectId": "cb50f1d6-7a11-44d7-b45e-9c158b8e7774",
  "scope": "command",
  "repository": "acme/widgets",
  "command": "deploy",
  "permission": "write",
  "effect": "allow"
}
```

| Field | Required | Notes |
| --- | --- | --- |
| `subjectType` | yes | `user` or `team` |
| `subjectId` | yes | `users.id` or `teams.id`; must belong to the org |
| `scope` | yes | `org`, `repository`, or `command` |
| `repository` | when scope is `repository` or `command` | `owner/repo` |
| `command` | when scope is `command` | command name |
| `permission` | yes | `read`, `write`, or `admin` |
| `effect` | no | `allow` (default) or `deny` |

Success: `200 OK`.

```json
{
  "id": "3b6d4f12-9a41-4f88-a1c5-8a4d4b6e9f10"
}
```

| Status | Meaning |
| --- | --- |
| `200` | Grant created |
| `401` | No valid session |
| `403` | The caller is not an org owner |
| `409` | An identical grant already exists (org-scope duplicates included) |
| `422` | Validation failed (bad subject/scope/fields, or subject not in org) |
| `500` | Creation failed |

## DELETE `/api/grants/{id}`

Deletes one grant, scoped to the caller's org (a grant in another org is not
found).

```sh
curl -b cookies.txt -X DELETE \
  https://slash.example.com/api/grants/3b6d4f12-9a41-4f88-a1c5-8a4d4b6e9f10
```

Success is `204 No Content`. An unknown grant returns `404`; a non-owner
returns `403`.

## GET `/api/org/members`

Lists the org's users and teams for use as grant subjects.

```sh
curl -b cookies.txt https://slash.example.com/api/org/members
```

Success: `200 OK`.

```json
{
  "orgId": "b07dc85d-d18c-42fa-9a58-055d9f32801c",
  "users": [
    { "id": "1165fc2c-64f4-49f6-b77c-15317cf59fb8", "name": "Release Operator" }
  ],
  "teams": [
    { "id": "cb50f1d6-7a11-44d7-b45e-9c158b8e7774", "name": "eng" }
  ]
}
```

Same status codes as the other grants endpoints (owner-only).
