Slash serves its HTTP API and web console from the same origin. Replace
`https://slash.example.com` in the examples with the origin of your Slash
deployment. The console (see the [web console guide](/en/web-console/)) is a
thin client over these same endpoints.

All request bodies share a **5 MiB limit**. UUID path parameters use the
standard hyphenated UUID representation. Timestamps in JSON responses are
RFC 3339 strings.

## Authentication methods

| Surface | Authentication |
| --- | --- |
| Account, team, and Test Engine management | `slash_session` cookie issued by register or login |
| Test result ingestion and quarantine lookup | `Authorization: Bearer <collection-token>` |
| GitHub webhook | `X-Hub-Signature-256` HMAC signature |
| Health and metrics | None |

## Endpoint inventory

The tables below list every route registered by `slash-server`.

### [Authentication and teams](/en/api/authentication/)

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Create an account and session |
| `POST` | `/api/auth/login` | Create a session |
| `POST` | `/api/auth/logout` | Clear the current session |
| `GET` | `/api/auth/me` | Read the current user, teams, and connections |
| `GET` | `/api/auth/github/sign-in` | Start GitHub sign-in |
| `POST` | `/api/auth/github/connect` | Connect GitHub to the current user |
| `GET` | `/api/auth/github/callback` | Complete GitHub authentication |
| `POST` | `/api/teams` | Create a team |

### [Grants management](/en/api/grants/)

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/grants` | List the org's grants (owner-only) |
| `POST` | `/api/grants` | Create a grant (owner-only) |
| `DELETE` | `/api/grants/{id}` | Delete a grant (owner-only) |
| `GET` | `/api/org/members` | List the org's users and teams for grant subjects (owner-only) |

### [Test Engine management](/en/api/test-engine/)

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/test-engine/suites` | List owned suites |
| `POST` | `/api/test-engine/suites` | Create or reuse a suite |
| `GET` | `/api/test-engine/suites/{id}/tests` | List tests in a suite |
| `GET` | `/api/test-engine/tests/{id}/executions` | List execution history |
| `PATCH` | `/api/test-engine/tests/{id}/state` | Change a test's disposal state |
| `GET` | `/api/test-engine/suites/{id}/tokens` | Read the latest active token |
| `POST` | `/api/test-engine/suites/{id}/tokens` | Issue a collection token |
| `POST` | `/api/test-engine/suites/{id}/tokens/revoke` | Revoke a collection token |

### [Test result ingestion](/en/api/ingestion/)

| `POST` | `/v1/test-engine/upload/vitest` | Upload Vitest results |

## Error conventions

Account and team endpoints return JSON errors in this shape:

```json
{
  "error": "invalid email"
}
```

The create-suite endpoint uses `{ "message": "..." }` for validation and
ownership conflicts. Other Test Engine management and ingestion failures may
return an empty body with the HTTP status documented for the operation.

Unknown `/api/*` routes return `404` with `{ "error": "not found" }`.
