Slash serves its HTTP API and web console from the same origin. Replace
`https://slash.example.com` in the examples with the origin of your Slash
deployment. The console (see [Account and workspace](/en/account/)) is a
thin client over these same endpoints.

All request bodies share a **5 MiB limit**. UUID path parameters use the
standard hyphenated UUID representation. Timestamps in JSON responses are
RFC 3339 strings.

## Choose an API

- Use [Authentication and teams](/en/api/authentication/) for sessions,
  external identity, the current user, and team creation.
- Use [Personal access tokens](/en/api/access-tokens/) to issue credentials
  for agents and other REST clients.
- Use [Command activity](/en/api/activity/) for browser-only GitHub repository
  discovery and authorized invocation history.
- Use [Test Engine management](/en/api/test-engine/) for suites, tests,
  execution history, state, and collection tokens.
- Use [Test result ingestion](/en/api/ingestion/) from CI to upload results or
  query quarantine.
- Use [Webhook and operations](/en/api/platform/) when configuring or
  monitoring the server boundary.

## Authentication methods

| Surface | Authentication |
| --- | --- |
| Account, team, and Test Engine management | `slash_session` cookie or personal Bearer token |
| Password credential management | `slash_session` cookie only |
| Personal access token management | `slash_session` cookie only |
| Command activity and GitHub repository discovery | `slash_session` cookie only; discovery also requires the encrypted GitHub access cookie |
| Test result ingestion and quarantine lookup | `Authorization: Bearer <collection-token>` |
| Instance administration | Separate admin session enabled by `SLASH_ADMIN_SECRET_PATH` |
| GitHub webhook | `X-Hub-Signature-256` HMAC signature |
| Health and metrics | None |

## Endpoint inventory

The tables below list every route registered by `slash-server`.

### [Authentication and teams](/en/api/authentication/)

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Create an account and session |
| `POST` | `/api/auth/login` | Create a session |
| `PUT` | `/api/auth/password` | Create or replace the current user's password credential |
| `POST` | `/api/auth/logout` | Clear the current session |
| `GET` | `/api/auth/me` | Read the current user, teams, and connections |
| `GET` | `/api/auth/github/sign-in` | Start GitHub sign-in |
| `POST` | `/api/auth/github/connect` | Connect GitHub to the current user |
| `POST` | `/api/auth/github/repository-access` | Refresh repository-discovery authorization |
| `GET` | `/api/auth/github/callback` | Complete GitHub authentication |
| `POST` | `/api/teams` | Create a team |

### [Personal access tokens](/en/api/access-tokens/)

| Method | Path | Purpose |
| --- | --- | --- |

| `DELETE` | `/api/access-tokens/{id}` | Revoke a token |

## Error conventions

Account and team endpoints return JSON errors in this shape:

```json
{
  "error": "invalid email"
}
```

The create-suite endpoint uses `{ "message": "..." }` for validation and
ownership conflicts. Other Test Engine management and ingestion failures may
return an empty body with the HTTP status documented for the operation.

Unknown `/api/*` routes return `404` with `{ "error": "not found" }`.
