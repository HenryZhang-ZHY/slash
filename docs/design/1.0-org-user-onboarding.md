# Slash 1.0 — 用户 Onboarding(登录 + 建 Team)设计

> 作者: @SlashOrg。日期: 2026-08-11。Status: implemented (MVP), aligned with Henry.
> 原则: ① ToB CI SaaS 建模, 配置放**应用数据库**; ② Buildkite 教训 —— 核心管理原语是
> **User 和 Team**, Organization 只是薄租户/命名空间容器; ③ 不和 GitHub 绑死: slash 自有
> 账号密码 authN, GitHub 只做后续 actor 识别与执行面。

> GitHub 登录与显式账户连接的后续产品规则见
> [`github-authentication.md`](github-authentication.md)。该设计仍定义自有账号、Team 与
> Organization；外部身份不再直接存放在 `users` 表中。

## 1. Scope(MVP)
1. **账号密码注册 + 登录**(slash 自有 auth, HttpOnly 会话 cookie)。
2. 登录后引导**创建 Team**(Team 是访问控制中心)。建 team 时自动为其创建/复用租户组织。
3. 建完 team → onboarding 完成。

后置: grants 授权、invitations、organizations 多对象管理、SSO。

## 2. 数据模型(migrations/0006_org_users.sql)
- `users`(id uuid, email 唯一, password_hash argon2, display_name, status,
  github_user_id/上 github_login 预留), `organizations`(薄容器), `teams`(访问控制中心),
  `team_members`(user↔team, role member/maintainer)。

## 3. 后端(Rust, crates/slash-server)
- `auth.rs` — Argon2id 密码哈希(PHC)+ HMAC-SHA256 无状态会话 token, HttpOnly cookie。
- `userapi.rs` — `POST /api/auth/{register,login,logout}`, `GET /api/auth/me`,
  `POST /api/teams`(建/复用 org + 建 team + 加自己为 maintainer, 单事务)。
- `main.rs` — 路由 + URL 里的 `web_fallback`(静态资源 + SPA history 路由 fallback)。
- 会话配置: `SLASH_AUTH_SECRET` 环境变量; 前端目录 `SLASH_WEB_DIR`(默认 `web/dist`)。
- 新增依赖: `argon2`, `hmac`, `sha2`(均已加进 slash-server [dependencies])。

## 4. 前端(web/ —— React + ShadCN SPA)
- Vite + React 19 + TypeScript + Tailwind v4 + shadcn(base-ui)。`@/*` → `src/*`。
- 页面: `LoginPage`(登录/注册切换)、`OnboardingPage`(建 team)、`HomePage`(仪表盘/我的团队)。
- `lib/api.ts` 轻量 API client(`credentials: 'same-origin'`, 会话 cookie)。
- vite dev 将 `/api` 代理到 `localhost:8080`; 生产由 slash-server 同源托管 `web/dist`。

## 5. 验收(MVP, 已手动验证 + 测试)
1. 注册 / 登录 / me / 建 team / logout 全链路通。
2. 未登录访问受保护端点 → 401; 错误密码 → 401; 重复注册 → 409。
3. 建 team 自动建 org, 用户成为 maintainer。
4. 密码 argon2 存储; 会话 HttpOnly cookie 不暴露 JS。
5. SPA 路由 `/` `/login` `/onboarding` → 200; 未知 `/api/*` → 404。
6. `cargo clippy -D warnings` 0 warning; `cargo test -p slash-server` 76 通过。
